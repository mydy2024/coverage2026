# 07 无工程环境时的离线路线

用户当前无法提供DDR5工程、运行主机、仿真器和monitor/interface信息。近期开发以此为已知约束，不再将这些信息作为继续开发的前置条件。既有真实环境接入计划保留，待条件具备后再执行。

本次调整的是工作顺序和验收边界，不是把教学重放升级为DDR5仿真。本文列出的新增工作均为待实施；已有能力和测试记录见[06 首版实现与接入](06_首版实现与接入.md)。

## 1. 现在的目标

先构建独立于厂商工具和具体testbench的验证核心：

```text
规格与声明的假设 → 可执行规则 → collector生成
                               ↓
独立预期 + 离线事件轨迹 → 重放/差分 → 故障定位候选
                                      ↓
                               修复 → 回归 → 证据报告
```

这可以验证框架的规则表达、历史状态、诊断和追溯能力。它不能证明真实DDR5 DUT行为正确、已有monitor解码正确或仿真器covergroup实际计数正确。

## 2. 优先工作清单

| 顺序 | 工作 | 验收证据 | 不需要的输入 |
|---|---|---|---|
| O1 独立离线基准 | 将人工预期结果独立存档；补充复位、跨rank、epoch变化、无效事件、多规则共享事件场景 | 输入轨迹与人工预期逐项对照；预期不能调用被测重放器生成 | DUT、仿真器、内部工程 |
| O2 采样语义与IR扩展 | 在现有min_interval上逐项增加经定义的时间窗口、条件适用性和更明确的事件锚点 | 每个新原语有正/负/边界反例，生成器和解释器消费同一明确契约；SV前端通过 | 私有interface及信号层级 |
| O3 证据驱动诊断 | 对错误阈值、漏采、错scope和缺边界轨迹构造受控故障；输出支持/反对证据及unknown | 故障标签对诊断器隐藏；可区分时定位，不能区分时拒判；无证据不生成概率 | 真实工程故障标签 |
| O4 修复与回归 | 修复候选记录旧新版本、影响集、最小反例及回归结果 | 修复后独立预期通过；无关用例无退化；旧结果标stale；不删目标抬高比例 | 仿真集群、原生coverage数据库 |

下一项优先完成O1，再做O3的最小案例；不要同时扩展大量协议原语。O2按诊断实验确实需要的能力逐个引入。

原有27项Python测试和3种SV静态检查是基础。O1需把独立预期、基准清单及故障注入证据组织成可重跑的实验包，而不只是增加同构单元测试。

## 3. DDR5规格工作仍能推进

可以继续从本地JESD79-5D整理VrefCA/VrefCS的要求、参数引用、图示起止点、脚注和适用条件。每个问题区分：

- **规范可解**：通过正文、表、图和相邻章节继续核查，不因为没有工程就全部搁置。
- **实现相关**：设备配置、tCK、具体monitor信号、训练状态来源等，记录为未来adapter/config输入。
- **仍有歧义**：保留draft及明确问题，不凭旧代码自动裁决。

在规范语义已核对后，可以为明确声明的假设配置创建独立离线profile。profile中的假设与推导要有来源；它代表“该模型及假设下的分析”，不能冒充用户实际器件配置。

当前`examples/ddr5_vref/plan.draft.json`仍保持blocked。后续若创建可执行离线profile，应另建文件和版本，保留原草案的未决问题，不通过清空blockers伪造接入完成。

## 4. 采样与interface的处理

目前继续使用统一命令事件契约。离线事件生产器承担“提供输入数据”的职责，不声称自己是DDR5 DUT或可信硬件monitor。collector消费已经解码并带时间、scope和epoch的事件。

不需要为了暂时拿不到工程而重写整套DDR5 interface/decoder。将来获得环境后，在现有monitor与事件契约之间新增adapter；若缺少CS边沿等观测，再补局部探针。

SV前端静态检查继续进行。若以后引入可用HDL运行工具，先用小例子核实所需语法和covergroup能力，再加入动态对拍；在确认工具能力前不把该步骤列为当前必过门槛。

## 5. 离线完成与工程关闭分开计量

| 结果 | 可使用的表述 | 尚不能使用的表述 |
|---|---|---|
| 人工轨迹达到所有目标 | 声明模型下的离线目标命中 | 实际DDR5覆盖收敛 |
| 修复后独立预期通过 | 离线缺陷修复与回归通过 | DUT缺陷已修复 |
| 生成SV通过slang检查 | SV语法与静态语义检查通过 | 商业仿真运行通过或Python/SV动态等价 |
| 给定模型中发现配置矛盾 | 指定假设下的目标矛盾 | 实际设计全局不可达 |

当前`closure_claim=false`、verified coverage未认证的行为保留。若为离线实验新增完成指标，应另设字段并明确命名，不能复用真实工程的关闭标志。

真实环境阶段暂缓：monitor绑定、DUT运行、native coverage计数对拍、独立checker汇合、真实配置可达性及M0/M1工程验收。原8周计划属于环境可用后的参考排期，当前等待时间不计作已完成进度。

## 6. 未来接回工程时

届时再补环境信息，不要求现在提供占位主机、猜测路径或私有文件。接回顺序保持为：真实事件适配→采样时序核对→边界轨迹动态对拍→native coverage与checker汇合→工程关闭判定。

离线路线保留同一套ID、规则和证据模型，使未来接入集中在adapter与验证证据层，而不重写整个框架。
