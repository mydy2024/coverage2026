## 2. O1 做了什么

### 2.1 独立存档的人工预期

`cases.json` 包含 13 个场景，每个场景的预期结果由人工根据 `spec.md` 语义推导，不调用被测重放器生成。每个场景附带 `rationale` 字段记录推导过程。

### 2.2 逐项对照

`harness.py` 对每个 sample 逐字段比较：

| 字段 | 说明 |
|---|---|
| `rule_id` | 命中的规则 |
| `end_event_id` | 结束事件 |
| `start_event_id` | 起始事件（无历史时为 null） |
| `outcome` | at_bound / above_bound / below_bound / suppressed |
| `interval_ticks` | 测量区间（抑制时为 null） |
| `bin_id` | 命中的 bin（违例/抑制时为 null） |
| `suppression_reason` | no_history / invalid_observation / null |

同时比较 summary 聚合指标（total_bins、replay_observed_bins、replay_observation_ratio、replayed_violations）、duplicates_ignored 和 diagnostics 列表。

### 2.3 场景覆盖

| # | 名称 | 覆盖能力 | 07 文档要求 |
|---|---|---|---|
| 01 | at_bound | 边界命中 | — |
| 02 | above_bound | 超出边界命中 | — |
| 03 | below_bound_violation | 违例不计入合法覆盖 | — |
| 04 | no_history | 无起始历史时抑制 | — |
| 05 | latest_start_wins | latest_start 策略 | — |
| 06 | reset_clears_history | 复位清除历史 | **复位** |
| 07 | cross_rank_independent | 跨 rank scope 隔离 | **跨 rank** |
| 08 | config_epoch_change | config_epoch 变化清除历史 | **epoch 变化** |
| 09 | reset_epoch_change | reset_epoch 变化清除历史 | **epoch 变化** |
| 10 | invalid_event_clears | 无效事件抑制并清除历史 | **无效事件** |
| 11 | duplicate_idempotent | 精确重复幂等 | — |
| 12 | self_overlap | 命令既是 start 又是 end | — |
| 13 | multi_rule_shared | 多规则共享事件 | **多规则共享事件** |

07 文档 O1 要求的 6 类场景（复位、跨 rank、epoch 变化、无效事件、多规则共享事件）全部覆盖。

## 6. 下一步

按 07 文档建议：**先完成 O1，再做 O3 的最小案例；不要同时扩展大量协议原语。O2 按诊断实验确实需要的能力逐个引入。**

O1 已完成。下一项是 O3（证据驱动诊断）的最小案例：
- 对错误阈值、漏采、错 scope 和缺边界轨迹构造受控故障。
- 故障标签对诊断器隐藏。
- 可区分时定位，不能区分时拒判。
- 无证据不生成概率。
