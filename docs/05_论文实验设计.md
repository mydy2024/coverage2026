# 05 论文实验与贡献边界

## 1. 研究问题

建议研究主题：**规格可追溯的覆盖闭环中，事件级证据和受控重放能否减少错误归因与错误关闭，并降低达到固定覆盖目标的成本？**

三层 IR 和依赖 DAG 已是 ChatFCM 的主要内容，不作为本工作的独立首创。候选新增贡献是：版本化 requirement→bin→运行证据链；以区分实验驱动上下游修复；约束模型变更、证据失效和不可达排除的可审计关闭机制。它们是否有新颖性与实验优势仍需后续更完整的相关工作检索和实测确认。

不建议在现阶段使用“首次”“必然收敛”“贝叶斯自动识别因果根因”或“已超越 ChatFCM”的主张。只基于所给三份材料不足以证明这些结论。

## 2. 三组相互分开的实验

| 实验 | 保持固定的对象 | 主要问题 |
|---|---|---|
| E1 模型构建正确性 | 原始规格、人工checkpoint、隐藏golden轨迹 | 提取、生成和采样是否正确？ |
| E2 固定模型覆盖搜索 | 经独立验证的同一模型、同一目标分母 | 诊断/定向激励是否更快达到合法目标？ |
| E3 故障条件下闭环 | 同一故障集、隐藏oracle和固定评测目标 | 能否定位、修复，并避免虚假关闭？ |

不能在 E2 中让一种方法改 model/bins，另一种只能调 stimulus。E3 允许修模型，但评价通过隐藏固定 oracle，禁止靠弱化 guard、删除 bin 或改分母取胜。

## 3. 基线与消融

| 编号 | 方法 | 比较目的 |
|---|---|---|
| B0 | 已验证模型 + constrained random | 现有仿真流程成本基线 |
| B1 | 相同模型 + LLM读取coverage反馈与等价原始规格片段，无结构图 | 分离LLM建议与结构化关联收益 |
| B2 | 相同模型 + 确定性诊断规则/定向模板 | 证明LLM或概率层是否值得引入；这是强基线 |
| B3 | 证据图 + 事件差分 + probe + 双向修复 | 核心完整方法 |
| B4（可选） | B3 + 校准后的概率排序/实验选择 | 研究概率层边际收益 |
| Human（可选） | 相同信息权限下工程师分析与修复 | 工程成本参考；不强行与自动方法合并统计 |

若拿不到 ChatFCM 原代码及其 checkpoint 数据，只能写“按论文描述实现的 ChatFCM-style 构建基线”，不能声称复现了作者系统。文件名含 ICCAD26 不足以证明正式发表状态。

消融项：去掉来源/版本失效；去掉事件 witness；去掉区分实验；只下行补激励、不上行修模型；去掉不可达证据 gate；去掉LLM；最后比较有无概率排序。选择能回答研究问题的组合，避免全部组合爆炸。

## 4. 故障集

首轮验收集建议 12 个有独立预期的小案例；论文候选集扩展为约 40–60 个不同机制的实例，规模是规划值。按规则族或变异机制划分开发/验证/测试，不能只把同一模板换 seed 后随机分割。

| 家族 | 注入例 | 真值与预期 |
|---|---|---|
| A 规格/IR | 错误阈值引用、遗漏MR条件、错误scope、脚注遗漏 | 独立规范审阅与golden反例 |
| B 解码/采样 | CA位错误、漏valid、事件晚一拍、reset不清历史、错rank关联 | 原始pin与oracle、SV逐事件差分 |
| C 激励 | 约束只允许大于阈值、特定合法命令未运行 | 模型无误，定向实际执行后可命中 |
| D 配置不可达 | 冻结模式与bin要求矛盾 | 约束集合与证明；改变配置应解除排除 |
| E 环境/导出 | 断开binding、丢失coverage文件、重复导入、版本错配 | 应拒绝计分或重跑，不能误判A–D |
| F DUT | 已知合法刺激下的可控DUT缺陷 | 独立checker报错，不能通过修改coverage掩盖 |
| 组合与unknown | A+B、B+C、可达性超时、缺日志 | 多标签或拒判；不能强制单一根因 |
| 无故障对照 | 正确模型但难命中的合法场景 | 统计误报与不必要修改 |

每个 mutant 都要确认：确实改变了对象；独立 oracle 上可产生影响；是单故障还是组合故障；是否与另一个变异等价。未生效和等价变异单独报告，不能算成功检出或悄悄删除。

注入标签、golden修复、隐藏测试不提供给诊断器。由另一位熟悉协议的工程师审阅关键案例；现有旧 KG 与生成器同时用于构造和评判会产生共享错误。

## 5. 指标

| 指标 | 定义与解释 |
|---|---|
| 要求建模完整度 | 独立 scope 中已正确落实的要求比例；不等同于运行hit |
| 模型事件精确率/召回率 | 对oracle的采样事件与bin分类，分别统计漏采、误采、错分类 |
| Trace completeness | 全链必需引用均解析且证据有效的目标比例；字段存在不算完成 |
| Verified coverage curve | 按02文档固定分母计分，横轴为仿真周期/CPU时间/总成本分别作图 |
| Time/cost to target | 达到预先声明目标的成本；未达目标记censored/失败，不能丢弃 |
| Diagnosis | top-1/top-k、宏平均F1、多标签指标、拒判比例及接受预测上的准确率 |
| Repair success | 隐藏反例通过且必要回归无退化的修复比例 |
| False closure | 宣称关闭但独立oracle仍存在违反目标的案例数/关闭案例数 |
| Exclusion precision | 被标严格不可达中证据和范围均成立的比例；bounded/unknown单列 |
| Replay reproducibility | 相同manifest重放得到相同语义结论的比例 |
| Cost | LLM调用/token、仿真CPU、wall time、license等待、人工审阅时间分别报告 |

概率版本额外评价 Brier score、可靠性曲线及分组校准。概率标签必须明确是“某缺陷存在”还是“某动作成功”；二者不能共用一个含糊 confidence。

前期每策略至少 5 个配对随机 seed 做可行性检查；正式组以方差和预算确定数量，建议先估算 10–20 个独立 seed。报告中位数、分布与置信区间，按独立运行或规则族聚类重采样；不要把同一次运行中几千个相关 bin 当作几千个独立样本。

## 6. 公平性与可复现性

冻结：规范哈希、DUT/TB、IR/plan、模板、仿真器、运行选项、配置、随机seed清单和预算。LLM设置记录实际可用模型标识、prompt与响应哈希、重试和失败成本；不在规划里指定未经核对的当前商业模型价格或能力。

各自动组使用相同可观测信号与基本工具权限。专门测试“无图”的基线仍可获得等价原文内容，否则无法区分信息数量与图结构收益。失效运行的成本也要计入。

每次实验产出 run_manifest、原始coverage、事件证据、checker日志、决策轨迹、修复diff、排除证明、closure报告。报告图能从保存的原始数据重新生成，不能只留下汇总百分比。

Vref单规则族的演示只能支持窄范围结论。论文若希望主张通用 DDR5 闭环，应在第一族稳定后增加独立命令/状态或时序规则族，并划出未参与调参的测试族；不必直接扩到完整LPDDR5。

## 7. 预定图表

一张架构与证据图；一张IR错/采样错/激励缺失的同症状区分案例；多seed覆盖-成本曲线；诊断混淆与拒判；修复成功/虚假关闭/错误排除表；跨版本失效与重放案例；一个unknown或失败案例。所有结果留待真实执行，不预填“预期提升xx%”。
