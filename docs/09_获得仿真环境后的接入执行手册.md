# 09 获得仿真环境后的接入执行手册

本文是 DDR5 Vref coverage v1 的真实工程接入操作清单。拿到仿真主机、DUT/TB、
monitor 和商业仿真器后按顺序执行；任何 gate 失败都先保留日志并停止升级状态，不能把
编译失败、导出失败或采样不可信记成零覆盖。

目标是把当前状态从：

```text
SV静态检查通过、暂定事件接口
```

推进到：

```text
真实monitor事件 → Vref collector → native coverage + checker + waveform witness
```

## 1. 环境到手后先收集什么

不要立刻修改 DUT/TB。先建立一份只读环境快照，至少记录：

| 项目 | 需要记录的内容 | 示例命令或来源 |
|---|---|---|
| 仿真主机 | hostname、OS、运行账号 | `hostname`; `uname -a` |
| 仿真器 | 工具名、完整版本、license是否可用 | `vcs -ID`; `xrun -version`; `vsim -version` |
| 工程位置 | DUT/TB绝对路径、工作目录 | `pwd` |
| 代码版本 | DUT、TB、VIP、monitor的commit或发布版本 | `git rev-parse HEAD` |
| 已有smoke | 一条原样可成功运行的编译和测试命令 | Makefile/回归脚本 |
| test/seed | 默认测试名、seed传入方式 | 原有run脚本 |
| monitor | 解码命令的类/module/interface及调用位置 | 文件绝对路径和符号名 |
| checker | scoreboard/assertion入口及结果日志 | 文件和报告位置 |
| coverage | 开关、数据库目录、文本/XML/UCIS导出方式 | 原有coverage脚本 |
| 波形 | FSDB/VPD/SHM/WLF开关和输出位置 | 原有dump脚本 |
| DDR5配置 | speed、tCK、1N/2N、rank/subchannel、MIR/CAI、MR2[4] | test配置及初始化日志 |
| 可控性 | 能否定向产生VrefCA/VrefCS和T-1/T/T+1间隔 | sequence/driver能力 |

把原始命令、日志和版本号保存在一次接入记录中。不要只写“VCS可用”或“测试通过”。

## 2. 填写环境配置并做发现检查

编辑 `configs/environment.json`：

```json
{
  "simulator": "vcs",
  "workdir": "/absolute/path/to/ddr5/project",
  "smoke_argv": ["make", "smoke", "TEST=existing_test", "SEED=1"],
  "monitor_path": "/absolute/path/to/decoded_command_monitor.sv"
}
```

要求：

- 全部使用真实绝对路径，不填旧主机路径或占位符；
- `smoke_argv` 按argv逐项填写，不拼成一个shell字符串；
- `monitor_path` 指向实际产生观测事务的monitor，不是driver sequence；
- 配置中不要写license密码、token或其他凭据。

先运行只读检查：

```bash
cd /path/to/2026DAC
python cc.py doctor --config configs/environment.json
```

`doctor` 只检查路径和工具，不会执行smoke。期望状态是
`configured_not_tested`；仍有 blocker 时先解决环境事实，不进入绑定。

## 3. 先重跑未修改的工程基线

在没有加入 coverage 文件之前，原样执行已有 smoke：

```bash
cd /absolute/path/to/ddr5/project
<existing compile command>
<existing run command with fixed test and seed>
```

保存：

- 完整compile/elaborate/run命令；
- stdout/stderr原始日志；
- 退出码；
- test、seed和配置；
- DUT/TB/monitor/checker版本；
- checker结果；
- coverage数据库和波形路径；
- 运行产物哈希或manifest。

验收：原工程在未接入 collector 时可重复通过。同一 test/seed 连续运行两次时，关注的
命令序列应在语义上可复现。基线失败时先标记 `E_ENV`，不要修改 coverage 来掩盖。

## 4. 在目标仿真器上运行独立 SV smoke

将 `delivery/ddr5_vref_v1/` 同步到仿真工作区，在该目录编译：

```text
# VCS示例
vcs -sverilog -f ddr5_vref_smoke.f -top ddr5_vref_smoke_tb -o simv
./simv

# Xcelium示例
xrun -sv -f ddr5_vref_smoke.f -top ddr5_vref_smoke_tb

# Questa示例
vlog -sv -f ddr5_vref_smoke.f
vsim -c ddr5_vref_smoke_tb -do "run -all; quit -f"
```

具体license和coverage选项沿用工程已有脚本。期望日志包含：

```text
DDR5 Vref coverage smoke test PASS
```

同时确认目标仿真器能建立两个covergroup及其cross。编译成功但covergroup未进入数据库，
仍不算通过。保存compile、run和coverage导出日志。

## 5. 实现真实 monitor adapter

复制 `delivery/ddr5_vref_v1/ddr5_vref_adapter_template.sv` 为工程内正式adapter，
例如 `ddr5_vref_cov_adapter.sv`。不要直接修改collector来适配层级。

adapter必须完成以下映射：

| collector输入 | 从真实工程取得 | 要验证的事实 |
|---|---|---|
| `timestamp_fs` | monitor不可变事务快照或明确采样边沿 | 转成整数fs后不丢半周期精度 |
| `channel/subchannel/rank` | monitor transaction或interface | scope与规范规则一致 |
| `config_epoch` | speed/MR/1N-2N等配置变化管理 | tCK或相关MR变化前递增 |
| `reset_epoch` | reset monitor | reset后递增且不回退 |
| `tck_fs` | 当前实际时钟周期 | 与波形及speed配置一致 |
| `is_reset` | reset语义事件 | 对所有受影响scope发出或递增epoch |
| `command_valid` | monitor解码有效标志 | X/Z、截断或歧义时为false |
| `command` | 现有命令枚举 | 显式映射到`ddr5_vref_cmd_e` |

调用必须发生在monitor完成事务快照之后，不能在driver发请求时调用。一个scope内的
timestamp必须严格递增；同一时刻存在多个语义事件时，先扩展事件顺序契约，不能随意排序。

如果已有monitor不能区分VrefCA/VrefCS、无法识别多周期命令或没有rank信息，只补局部
probe/adapter；不要先重写整个DDR5 decoder。

## 6. 审核Vref多周期锚点

这是接入前必须人工确认的语义gate。结合JESD79-5D Figure 117/118、Table 125/127、
MR2 OP[4]、1N/2N配置和实际monitor采样方式，书面确认：

1. VrefCA/VrefCS语义事件在哪个CA/CS边沿成立；
2. 多周期命令的重复原始采样如何合并为一个事件；
3. start timestamp取首边沿、末边沿还是规范指定锚点；
4. 后续valid command的end timestamp取哪个边沿；
5. NOP与DES是否被正确排除；
6. MIR/CAI处理发生在命令判定前还是后；
7. `tMRD=max(14ns,16*tCK)`对当前目标配置是否成立。

用一条真实Vref波形标注原始CA、CS、解码事件、start/end timestamp和计算出的delta。
锚点未决时保持provisional，不允许用coverage hit关闭目标。

## 7. 接入文件和实例

目标工程的编译顺序至少为：

```text
ddr5_vref_cov_pkg.sv
ddr5_vref_cov_if.sv
ddr5_vref_cov_adapter.sv
```

在TB中实例化一个collector和adapter。示意：

```systemverilog
ddr5_vref_cov_if #(
  .NUM_CHANNELS(NUM_CHANNELS),
  .NUM_SUBCHANNELS(NUM_SUBCHANNELS),
  .NUM_RANKS(NUM_RANKS)
) vref_cov();

ddr5_vref_cov_adapter u_vref_cov_adapter (
  // 连接真实monitor事件
  .coverage(vref_cov)
);
```

首次只绑定一个明确的channel/subchannel/rank配置。编译、elaboration和run任一步失败，
本次run无效，不能登记为0% coverage。

## 8. 最小真实定向验证

先选最容易控制的两个关系，例如VrefCA→ACT和VrefCS→ACT。令当前阈值为T、仿真时间
精度为q，分别运行：

| 轨迹 | collector预期 | checker预期 |
|---|---|---|
| T-q | violation增加，合法bin不增加 | 必须检测或明确记录负向测试层级 |
| T | `at_bound`命中 | 通过 |
| T+q | `above_bound`命中 | 通过 |
| 无Vref直接ACT | suppressed | 不产生伪间隔 |
| Vref后reset再ACT | suppressed | 不跨reset |
| rank0 Vref、rank1 ACT | rank1 suppressed | scope隔离 |
| 配置变化后ACT | 旧历史失效 | 不沿用旧tCK |

每个结果都保留：test、seed、完整版本、波形窗口、start/end事件、tCK、T、delta、bin和
checker verdict。driver生成了意图但命令没有到达DUT接口时，不能记为真实样本。

## 9. 完整边界矩阵

最小切片通过后，对2个start命令和19个end命令执行：

```text
38 relations × (T-q, T, T+q)
```

至少覆盖三个tCK区域：

| tCK | tMRD期望 | 目的 |
|---:|---:|---|
| 1000 ps | 16 ns | `16*tCK`分支 |
| 625 ps | 14 ns | `14ns`分支 |
| 875 ps | 14 ns | 两个分支交界 |

完整计划为342个case。若实际控制器无法精确产生某个边界，记录
`stimulus_control_limit`，可在独立monitor replay层验证collector，但不能冒充真实DUT命中。

单个tCK配置的预期为：

- 38个`at_bound`关系命中；
- 38个`above_bound`关系命中；
- 38个violation，且不增加合法覆盖；
- 76个合法cross bins可在native coverage数据库中查询。

## 10. 导出并汇合运行证据

每个有效run至少导出三类结果：

1. native coverage数据库及可读bin计数；
2. monitor事件/witness，包含scope、epoch、timestamp、command、tCK和locator；
3. checker/scoreboard/assertion结果。

把真实elaboration路径回填到`delivery/ddr5_vref_v1/source_map.json`的
`native_paths`，不要猜实例层级。逐项核对：

```text
native bin hit
↔ collector sample
↔ start/end monitor event
↔ waveform窗口
↔ checker verdict
↔ Table 125/127规则
```

无法解释的额外计数、缺失witness、重复导入增长、coverage导出失败或checker失败都会阻断
`verified_hit`。

## 11. M0/M1完成条件

### M0通过

- 环境manifest、版本和原始smoke日志齐全；
- 未修改工程基线可重复运行；
- 目标仿真器能编译并运行独立Vref smoke；
- 当前配置的tMRD和Vref锚点已审核；
- 至少导出一个真实解码命令、一个coverage项和一个波形定位。

### M1通过

- adapter绑定到真实monitor，而不是driver；
- VrefCA和VrefCS各至少一组T-q/T/T+q通过；
- reset、scope和epoch场景通过；
- native bin、sample witness、checker与波形可以互相追溯；
- 相同test/seed的语义事件可复现；
- 所有失败和未决项仍保留，不通过删除目标提高比例。

完成M1后才能把交付状态从`provisional_interface_pending_real_tb_binding`升级为
`validated_on_<environment_revision>`。这仍不等于全部DDR5 coverage closure。

## 12. 环境到手后的最短操作顺序

```text
1. 记录工具/路径/版本/配置
2. 填environment.json并运行doctor
3. 原样重跑已有TB smoke两次
4. 在商业仿真器运行ddr5_vref_smoke_tb
5. 复制adapter模板并映射真实monitor事件
6. 用波形审核Vref多周期锚点和tMRD
7. 接入单个scope，跑VrefCA/VrefCS的T-q/T/T+q
8. 导出native coverage、事件、checker和波形
9. 对拍计数与witness，回填真实native path
10. 扩展到38关系和3个tCK区域
11. 保存证据bundle并执行M0/M1验收
```
