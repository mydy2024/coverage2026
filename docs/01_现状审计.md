# 01 现状审计与迁移判断

审计范围是 `../../causal_bayesian_attribution/` 及根目录旧 ReadME；现有成果更接近“DDR5 结构化提取与 decoder 生成原型”，尚不是完成的 coverage closure 系统。以下区分实际复现、静态证据和需仿真确认的风险。

## 1. 直接复现的问题

| 问题 | 本次证据 | 后果 | 处置 |
|---|---|---|---|
| 空运行报成功 | `run_pipeline.py --stage all` 与未知 stage 均返回 0，显示 `0/0 stages passed` | 自动化系统可能把未执行当验收成功 | 使用明确的参数枚举；未知 stage、零执行和必需阶段缺失均失败 |
| verify 只有文本检查 | `--stage verify` 返回成功；生成代码使用 UNKNOWN，自生成 enum 却没有 UNKNOWN | 不能据此声称可编译，更不能证明解码正确 | 将 compile/elaborate/semantic replay 分开计结果；UNKNOWN 独立定义 |
| KG 规则未控制生成 | 内存删除 `rule-cs-n-qualifier`，生成文本完全相同 | 来源注释不能证明规则落实到代码 | 建立 IR→生成节点映射与变异检查；必需规则缺失直接失败 |
| 独立参考不在当前交付目录 | `resource/` 不存在；recall 写死的 Q 盘路径不存在 | 历史 JSON 不能作为当前可复现证据 | 配置化参考路径、版本和来源；缺失报告 blocked，不把旧报告复用为本轮结果 |

复现详情和旧文件哈希保存在 [legacy_audit.json](../reference_notes/legacy_audit.json)。没有进行 HDL 编译，因此 UNKNOWN 的结论严格限定为“生成文件自身缺少声明，存在独立编译缺陷”；不冒充工具编译日志。

## 2. 方法论问题比脚本缺陷更关键

### 2.1 统计量名称与实际测量对象不一致

`pipeline/exp1_measure_pkg.py:213` 起用来源字段、完整度、结构清晰度、引用数量加权产生 `p_kg`。这些量可用于安排审阅优先级，未经真实标签校准，不能解释为 `P(语义正确)`。引用多可能只是重复传播同一个错误。

`pipeline/exp2_error_injection.py` 的 `diff_sv()` 用增删行数除以基准行数作为污染概率。旧报告中翻一个 pin 为 0.0081，删除 ACT 为 0.4615；这测到的是文本变化，并非某个事件被误解码的概率。enum 排序改变可扩大 diff，致命语义错误也可只改一个字符。比例甚至没有概率天然需要的上界约束。应改称 `text_change_ratio`，保留为调试量。

`pipeline/exp3_measure_pgen.py` 用 `source is not None` 的比例计算 `P_gen`，甚至空字典也计入。它测量来源字段存在率，不能证明引用页正确、语义正确或生成器正确。实现性辅助逻辑不来自规范也完全可能是正确的。

`audit_pipeline.py` 的主流程汇总现有 inline audit 分数，不能当作每次重新核对 PDF 的独立语义审计。审阅对象版本、引用片段、审阅动作和结论需要单独留档。

### 2.2 四阶段贝叶斯模型无法从 hit/miss 单独辨识根因

旧设计假设模型和仿真正常时，bin 以约 0.99 的概率命中。对于罕见场景、严格边界、受限随机策略，这个假设通常不成立。模型完全正确，也可以长期未命中。

命中至少取决于：配置适用性、场景可达性、激励是否被实际执行、DUT 行为、事件解码、历史状态、采样门控、bin 定义及导出过程。只观察总覆盖率，多个原因可产生相同结果。

旧文档的 `argmax |Δlogit|` 是信念变化最大，不等于后验错误概率最大，更不是因果根因证明；另一处写 `argmax Δ` 又与此不一致。将各节点后验边缘概率替换原 CPT 参数一般也不能保留更新后的联合依赖。跨轮累积 coverage 重复作为新证据会重复计数，同一轨迹产生的 bins 还可能高度相关。

本目录检索到的 `CausalBayesianAttribution` 为 Markdown 伪代码；未发现对应可执行推断器和基于真实仿真证据的实现。不能把设计文档当成已实现能力。

**替代方向：先通过分层对拍和受控重放产生可区分的证据；贝叶斯仅作为经过校准的诊断假设排序器。**

### 2.3 缺少端到端对象与事件级见证

当前 YAML 的来源字段是有价值的起点，但缺少统一文件哈希、稳定 requirement/bin ID、版本、代码映射、运行配置、采样 witness、修复影响范围、回归结果与关闭记录。改变 KG 后，也没有机制使旧命中证据自动失效。

`exp1_measure_recall.py` 把未实现的 sub-op 拆分算作 adjusted covered，并通过代码内集合排除 out_of_scope。可用于人工分析，不能作为冻结协议目标上的完成率。父命令存在不代表子操作解码完整。

## 3. 解码与时序风险

以下是需要在已有商业仿真环境中验证的风险；不将全部静态疑点宣称为已复现功能故障。

| 代码位置 | 风险/证据 | 必须做的检查 |
|---|---|---|
| `gen_decoder.py:165–186,264–345` | `cs_sampled` 与实时 `ca_proc` 混合，双周期又引用 `ca_history[1]` | 明确采样区间，逐周期对齐 CA/CS，连续双周期命令和复位插入对拍 |
| `gen_decoder.py:339–345` | PDX 条件为 `cs_sampled==1` 且上一条 PDE；JEDEC Table 30 续表列 PDX 的 CS_n=L | 这是需要修正的规范映射冲突；用真正 power-down 状态和退出序列验证，不能用 prev_cmd 代替状态 |
| `val_to_bit()` 与 casez | `V` 和 don't-care 都变成不匹配位，未见独立 known-value 检查 | JEDEC Table 30 note 1 区分 V=确定 H/L 与 X=don't-care；注入未知电平并核对处理 |
| 规则名称、硬编码模板 | 数据驱动粒度不一致，模板还内置协议语义 | 区分受支持的 typed op 与协议参数，拒绝未知 op 或缺失依赖 |
| `gen_rules.py` 的目标命令清单 | “any other valid command”被局部命令列表展开 | 新增命令不得悄悄漏掉约束；以合法命令语义集合展开并作范围审计 |
| 旧时序抽取 | 多周期 CS、MR2、图示测量端点和半周期边界尚需统一 | 不将 3.5 nCK 默默转为 4；参数、时间单位和采样锚点都须显式化 |

## 4. 保留、重构和停止沿用

| 资产 | 迁移方式 |
|---|---|
| `extract/`、`kg/commands.yaml`、timing、signals | 保留为候选数据；先标 imported/unreviewed，逐条补来源版本和适用配置 |
| `schema_def.py` | 借鉴字段、引用检查；增加唯一 ID、类型/单位、表达式 AST、时间状态与来源验证 |
| `gen_decoder.py` | 保留作对照和故障样本；暂不作为新闭环的唯一 monitor；通过对拍后逐步替换 |
| `gen_rules.py` | 借鉴展开方式，替换硬编码清单，增加 coverage obligation 层 |
| 错误注入函数 | 复用变异思路，加入注入生效检查、事件结果、独立 oracle 和多故障样本 |
| 旧 out/*.json | 标 legacy/unverified；不搬成新实验结果 |
| P_kg、P_gen、文本 δ | 重命名为明确的质量/来源/文本变化指标；停止直接送入概率模型 |
| 旧 runner | 重建 stage contract、运行 manifest、失败传播与结果新鲜度校验 |

迁移成功的标准不是“旧字段全部搬过去”，而是一个具体 bin 的规格、采样值、checker 结果和修复后的新证据能够完整回放。
